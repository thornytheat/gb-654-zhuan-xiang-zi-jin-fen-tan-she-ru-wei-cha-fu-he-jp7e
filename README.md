# 专项资金分摊与舍入尾差复核

面向一线复核人员的单服务数据工作台。样例数据随仓库提供，结论保留行号、原因码和原值。

## 业务模块

- M1 预算采信：`/api/budgets/import`
- M2 资格校验：`/api/eligibility/evaluate`
- M3 权重测算：`/api/weights/calculate`
- M4 金额分摊：`/api/allocations/calculate`
- M5 尾差裁决：`/api/remainders/resolve`
- M6 批次复核：运行摘要 `/api/runs`、批次拨款更正台账 `/api/batches`、遗留导出 `/api/export/allocations.csv`

## 核心规则

先迭代封顶再按有效权重分配，最后用最大余额法落到分；输入顺序变化不得改变结果。

## 批次拨款与更正台账（M6）

项目拨款后资格可能被撤销或封顶被调低。更正只追加快照版本，已拨款凭证与原批次金额原样留痕、绝不覆盖旧账；冻结旧账又会继续多拨，因此按更正后的资格重算应得，并与实付逐项目对账：

- 四列分列：每个项目分开列出 **应得、已拨、待补、待追回（未收回）**，已收回追回单列留痕。
- 未收回款不进入可再分配资金；可再分配现金 = 批复 − 累计已拨 + 累计已收回，待补超过现金池即形成资金缺口。
- 拨款/追回按凭证号幂等，重试不重复记账；拨款时点累计净拨款不得超过当时应得，更正后形成的超额转为待追回，凭证本身不修改。
- 并发更正采用乐观版本控制：发布时基线过期返回 `STALE_VERSION`（HTTP 422）。发布在单事务内完成，失败整体回滚保留旧版；发布中断后可对已存更正续跑，重试不重复记拨款或追回。
- 页面可对照更正前后应得差额、尾差与资金缺口；导出 `GET /api/batches/{batch_id}/export.csv` 始终带同一 `batch_id` 与当前 `data_version`，全部行属于同一批次。

## 启动

```bash
docker compose up --build
```

浏览器访问 `http://localhost:18213`。运行测试：

```bash
docker compose exec -T app pytest -q
```

## 样例流程

依次运行六个模块；最后在批次页复核输入、有效、隔离与输出合计。同一输入摘要重复执行时复用原 `run_id`。
批次台账流程：建立批次（v0 初始分摊）→ 登记拨款凭证 → 登记资格/封顶更正并发布 → 登记追回 → 在批次复核页对照四列台账与资金缺口 → 导出同批次 CSV。

## 已知不覆盖

不处理加密文件与需要外部密钥的对象；不连接真实生产存储。
